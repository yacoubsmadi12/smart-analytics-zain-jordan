# المرحلة الثالثة — نظام التصميم والاتساق البصري

**الحالة:** أُنجزت نواة المرحلة الثالثة، وأتوقف هنا للمراجعة قبل بدء المرحلة الرابعة، وفق نقطة المراجعة التي طلبها المستخدم.

## ملخص التغييرات

- إضافة `client/src/design-tokens.css` كمصدر مركزي لأساسيات اللون، ومستويات السطح، وحالات الألوان الدلالية، والخطوط ومقاساتها، والتباعد، وأنصاف الأقطار، والظلال، والحركة، وحلقة التركيز. أُضيف خط بديل متوافق مع العربية، وأرقام tabular، ودعم `prefers-reduced-motion`.
- تحميل الأنماط الأساسية والمشتركة على مستوى التطبيق، وتوحيد الهيكل العام عبر `PlatformShell`، مع إمكانية تبديل RTL/LTR.
- بناء مكتبة تحليلات قابلة لإعادة الاستخدام: `PageHeader`, `KpiCard`, `StatusBadge`, `ChartFrame`, `DataTable`, `FilterBar`, `DecisionCard`, `DetailDrawer`, و`AsyncState` لحالات التحميل والفراغ والخطأ ومنع الوصول، إضافة إلى مكوّن شرح الاختصارات.
- إعادة بناء Executive Overview باستخدام استعلامات المقاييس المركزية: خمس مؤشرات، أثر لأربع مناطق، رؤية تشغيلية واحدة مستمدة من مؤشرات CX، وأفضل ثلاثة قرارات؛ وتضم بطاقة القرار أربعة مقاييس أثر.
- إنشاء `/design-system` كمعرض حي للأساسيات والمكونات، مع بيانات مصدرية، وجدول قابل للفرز والتصفية والترقيم والتحكم بكثافة الصفوف، ولوحة تفاصيل، وحالات العرض، ونافذة تأكيد توضيحية وإشعار toast.
- جعل جداول الهاتف تتحول إلى بطاقات؛ مع إبقاء كل صف موسومًا بحقل `data-label`، وتثبيت حد حجم الصفحة عند 50 سجلًا كحد أقصى.
- ضغط بطاقات القرارات ومسافات Overview على الهاتف. أصبح ارتفاع Overview الكامل **2.94 شاشة** عند 390×844 بلا تمرير أفقي.

## قائمة التحقق

- [x] توكنز مركزية للألوان والخطوط والمسافات والأسطح والحركة والتركيز؛ أقل مقاس في السلم 12px.
- [x] فحص التباين حسابيًا على الخلفية والسطح الأول: النص الأساسي 16.54:1، الثانوي 11.47:1، المكتوم 7.55:1؛ وأضعف لون دلالي تم قياسه (الحالة الحرجة على السطح الأول) 5.95:1، أعلى من 4.5:1.
- [x] بطاقات KPI ذات أرقام tabular ومكوّنات للحالات والأخطاء والفراغ ومنع الوصول.
- [x] جدول بفرز وترقيم صفحات وكثافة قابلة للتبديل، وتفاصيل جانبية قابلة للإغلاق بلوحة المفاتيح.
- [x] عناصر الواجهة التفاعلية الأساسية ذات حد أدنى 44px، وحلقة تركيز مرئية، وتسميات مساعدة للأزرار والأيقونات.
- [x] عرض Responsive: سطح المكتب 1280px، اللوحي 1024×768 (ارتفاع محتوى Overview: 1911px، دون تمرير أفقي)، والهاتف 390×844 (2484px = 2.94 شاشة، دون تمرير أفقي، ومؤشرات KPI بعمودين).
- [x] اختبار RTL على الهاتف: `dir="rtl"` فعّال، دون تمرير أفقي؛ انعدام أخطاء JavaScript في جلسة الاختبار.
- [x] اختبار جدول المواقع على الهاتف: نمط الجدول `block` والصف `grid`، ظهر حقل المنطقة (Amman)، دون تمرير أفقي. اختُبر الانتقال من الصفحة 1/7 إلى 2/7، وتغير الفرز، ومفتاح كثافة الصفوف، وفتح لوحة تفاصيل الموقع.
- [x] اختبار فتح نافذة التأكيد التوضيحية؛ لا تنفّذ أي تغيير على سجلات فعلية.
- [x] `pnpm check` ناجح؛ `pnpm test` ناجح: 29 ملف اختبار؛ `pnpm build` ناجح.

## لقطات المراجعة

اللقطات محفوظة في `docs/screenshots/`؛ تشمل Overview على سطح المكتب واللوحي والهاتف وRTL، ومعرض النظام، وجدول الهاتف، وحالات المكونات، ونافذة التأكيد.

## ملاحظات وحدود

- صفحة `/design-system` معرض مرجعي طويل عمدًا لأنه يجمع أساسيات ومكونات وحالات متعددة؛ قيد الثلاث شاشات تم التحقق منه على صفحة Overview التشغيلية، لا على معرض المكونات الكامل.
- أظهر البناء تحذير Vite بشأن حجم بعض الحزم الأمامية الأكبر من 500KB؛ لم يمنع نجاح البناء، وسيدخل ضمن مراجعة الأداء في المرحلة الخامسة.
- المرحلة الرابعة (سير العمل والمهام والتنبيهات وCopilot والتقارير) **لم تبدأ** بعد. هذه الوثيقة نقطة مراجعة للمرحلة الثالثة فقط.
